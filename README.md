## 💡 О проекте

zapret-GUI позволяет управлять zapret без ручного запуска файлов стратегий.

## ✨ Возможности

- 🔌 Подключение и остановка из одного окна.

<a id="how"></a>
## ⚙️ Как работает программа

Готовая EXE-сборка включает интерфейс, движок zapret и стратегии. **Отдельно устанавливать zapret или Python для неё не требуется.**

При первом запуске приложение распаковывает встроенные компоненты в:

```text
%LOCALAPPDATA%\ZapretDesk\runtime
```

После нажатия «Подключить» программа при необходимости запрашивает права администратора, проверяет наличие другого запущенного winws.exe, запускает выбранную стратегию и проверяет доступность выбранных сервисов. При включённом автоподборе она пробует стратегии по очереди; при отсутствии ответов и от сервисов, и от контрольных узлов ожидает восстановления сети.

Импорт другой совместимой сборки — дополнительная возможность. Обязательной отдельной установки нет.

<a id="start"></a>
## 🚀 Начало работы

Готовый EXE распространяется отдельно от исходников. Порядок публикации сборок будет указан здесь после оформления релиза.

1. Распакуйте архив готового приложения и запустите EXE.
2. Выберите сервисы для проверки и включите автоподбор при необходимости.
3. Нажмите **«Подключить»**, подтвердите запрос прав администратора и дождитесь результата.
4. Для завершения работы движка нажмите **«Отключить»**.

<a id="help"></a>
## 🛠 Если подключение не работает

Откройте **«ЖУРНАЛ» → «Показать журнал»** или нажмите **«Сохранить отчёт…»**.

Файлы находятся в `%LOCALAPPDATA%\ZapretDesk` (путь можно вставить в окно **Win + R**).

| Файл | Содержимое |
|---|---|
| `desk.log` | Действия программы и ошибки подключения |
| `engine.log` | Вывод движка zapret |
| `startup-error.log` | Ошибки запуска приложения, если возникли |
| `runtime-error.log` | Ошибки подготовки встроенной сборки, если возникли |

При обращении во вкладке **Issues** укажите версию программы и Windows, шаги воспроизведения, выбранную сборку и стратегию. Приложите отчёт или журналы. **Перед отправкой проверьте их на наличие личных данных.**

В исправленной версии 0.7 проверка процессов использует Windows API и не зависит от `tasklist` или WMI. Это устраняет обнаруженный сбой подключения при ответе `tasklist` «Недопустимый класс».
