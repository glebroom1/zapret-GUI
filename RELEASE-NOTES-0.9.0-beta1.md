# Windows 0.9.0-beta.1 — диагностическая бета

Кандидат для prerelease, тег `v0.9.0-beta.1`. Подготовлен из отдельной копии Windows beta4; Android не изменялся. Публикация и commit остаются за nico.

## Исправления

- Короткий HTTPS-ответ YouTube больше не означает подтверждённое видео. Статус: «HTTPS · видео не проверено», без успешной записи в историю. У этой беты **нет проверенного автоматического медиатеста**. В авто при выбранном YouTube кандидаты не получают полный успех: подбор заканчивается без подтверждения. Для ручного использования остаётся выбранный работающий движок с честным непроверенным статусом.
- Автоподбор отделён от ручного включения: не оставляет последний профиль как якобы успешный. Один проход, общий бюджет 300 с; при лимите — отдельный результат. Отсутствие ответов приостанавливает перебор в пределах бюджета. После исчерпания процесс останавливается; автоматический бесконечный перезапуск аварийно завершившегося движка убран.
- STOP перестаёт ждать сетевой DNS/TLS. Проверки выполняются одной ограниченной группой фоновых потоков, ожидание не более20с, отмена проверяется каждые50мс. Заблокированный вызов системного DNS нельзя принудительно прервать: до его завершения следующая группа не создаётся, результат отменённого запроса не применяется.
- Старые события от STOP и проверки после изменения сети игнорируются. Локальный сетевой отпечаток учитывает активные интерфейсы/IP и исходный адрес системного маршрута. История дополнительно привязана к критерию, SHA256 движка и стратегии; срок предпочтения24ч. Это локальная идентичность, **не определение провайдера**: смена WAN за тем же маршрутизатором без изменения локальных данных может быть не замечена.
- Telegram остаётся отдельным worker. Он публикует возраст сетевого цикла отдельно от локального слушателя; доступность upstream обозначается непроверенной. После временного скачка часов/возобновления или смены физического интерфейса пересоздаёт backend/пулы, сохраняя PID, instance, порт и секрет. Прямой режим обновляет выбранный интерфейс каждые30с и при восстановлении; при его потере не переключается молча на системный маршрут.
- Предел задержки повторов пула после отказов upstream уменьшен с3600с до30с. Непредвиденное завершение backend допускает три повторных запуска с задержкой; STOP имеет приоритет. Это не watchdog зависшего интерпретатора: живой control-thread и задержанный event loop теперь различимы, автоматическое принудительное уничтожение не добавлялось.

Главная кнопка/дизайн, независимый winws, управление процессами с проверкой идентичности, сохранённые секреты, импорт/списки, updater и откат сохранены. Статические Android CDN/IP и ByeDPI-профили не переносились. Телеметрия, новые ключи и CI не добавлены.

## Проверки и ограничения

Подробные результаты — `reports/` в checks-архиве. **247 unit/integration тестов прошли** (237 существующих с обновлёнными ожиданиями нового контракта,10 новых). Включены импорт, updater, повреждённые данные, rollback, process identity и offscreen Qt. Старые тесты, считавшие HTTPS успехом YouTube, теперь проверяют partial либо используют Discord для проверки механики успешного HTTPS. Один тест импорта переведён с фиксированных200мс на ожидание окончания фоновой операции с пределом3с.

Проверки конечного EXE:36 встроенных модулей побайтно по нормализованному Python-коду совпали с исходниками; личные списки пустые; frozen worker/control/проверенная принудительная остановка/редакция секретов прошли. Настоящий frozen updater заменил только временный EXE с прежним именем в пути с пробелами, кириллицей и апострофом, сохранил предыдущий EXE и запустил новый `--smoke` с `errors: []`. Ошибки записи/занятого EXE/неудачного запуска и rollback проверены unit/integration fixtures, не объявлены испытанием сбоя питания.

Отдельный процессный тест Telegram22с с недоступным upstream и имитированным скачком времени сохраняет идентичность и завершает процесс по STOP. Это **не настоящий сон Windows и не Telegram-клиент**.

Сеть испытаний: Windows11 IoT Enterprise x64, Happ.exe/xray.exe активны, `happ-default-tun` имеет маршруты0.0.0.0/1 и128.0.0.0/1; Wi-Fi и Tailscale также включены. До запуска winws системные HTTPS YouTube/Discord ответили, контроль ya.ru дал TLS timeout. Эти ответы **не доказывают обход winws**.

Реальная активация WinDivert НЕ проверена: `Engine.start` корректно отказал без административных прав, отдельный CreateProcess для winws заблокирован Windows740 (требуется повышение). UAC/обход ограничения не выполнялся. Сеть, Happ, роутер и пользовательские настройки не менялись. Чужие winws перед/после не обнаружены и не останавливались.

Не выполнены: чистый Windows без окружения разработчика; физический маршрут без Happ; реальное видео/перемотка; пользовательский Telegram; физический сон/гибернация; 8-часовой soak; другие версии Windows/IPv6-only. Это диагностический prerelease, а не заявление о полном исправлении обхода.

EXE не имеет нашей Authenticode-подписи; SHA256 обеспечивает сверку файла, не заменяет подпись издателя. Windows может показать предупреждение SmartScreen. Обновление выполняется прежним механизмом с проверкой хеша и сохранением пути/предыдущего EXE; диагностическую бету не следует объявлять stable/latest.

## Передача публикации

`dist/` содержит EXE, переносимый Windows ZIP, source ZIP, checks ZIP, `update-windows.json`, этот отчёт, `PUBLISH-FILES.json` и SHA256SUMS. `PUBLISH-FILES.json` перечисляет точные пути и SHA256 исходников для commit; `reports/changed-files.json` сравнивает их с beta4. Рабочие/временные данные и секреты в source не входят. Никаких commit, git remote изменений или публикаций этим этапом не выполнено.

Документация Python по отмене проверена через Context7: https://github.com/python/cpython/blob/main/Doc/library/concurrent.futures.rst и https://github.com/python/cpython/blob/main/Doc/library/asyncio-task.rst. Уже исполняемый блокирующий вызов не отменяется вызовом Future.cancel; поэтому реализованы ограничение одной группы и отбрасывание устаревших результатов, а не обещание принудительной отмены DNS.
